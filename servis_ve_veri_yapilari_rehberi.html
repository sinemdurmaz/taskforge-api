⚡ 2. Veri Yapısı: Min-Heap & Priority Queue (heapq)

Yüzlerce görev arasından en acil olanı bulmak için $O(N \log N)$ yerine $O(1)$ kök erişimi sunan Min-Heap ikili ağacı:

Binary Min-Heap Ağaç Yapısı
[1] CRITICAL (Deadline: Bugün 18:00)
/                     \
[2] HIGH (Deadline: Yarın) [3] MEDIUM (Deadline: 3 Gün)
Neden Min-Heap? Min-Heap veri yapısında ağacın tepesi (Root) her zaman en küçük değere (yani en yüksek önceliğe) sahiptir. heapq.heappop() metodu ile en acil görev logaritmik zamanda çekilir. 
import heapq

# Puanlama: CRITICAL=1, HIGH=2, MEDIUM=3, LOW=4
heap = []
for task in tasks:
    weight = PRIORITY_WEIGHTS[task.priority]
    # Min-Heap'e ekle: O(log N)
    heapq.heappush(heap, (weight, task.deadline.timestamp(), task.id, task))

# En acil N görevi O(1) / O(log N) hızla getir:
most_urgent = [heapq.heappop(heap)[3] for _ in range(top_n)]

🔍 3. Veri Yapısı: Hash Set (set) ile O(1) Etiket Filtreleme

Etiket ararken liste üzerinde gezinmek yerine matematiksel küme kesişimi kullanıyoruz:

# Kullanıcının aradığı zorunlu etiketler
required_tags = {"backend", "security"}

# Görevin etiketleri küme (Set) olarak alınır:
# task_tags = {"backend", "security", "docker", "python"}

# O(1) Alt Küme Kontrolü (Subset check):
if required_tags.issubset(task_tags):
    # Görev tüm istenen etiketlere sahiptir!

Hash Set, elemanlarını bellek adreslerine göre indekslediği için bir elemanın kümede olup olmadığını ortalama $O(1)$ sürede doğrular.

🔀 4. State Pattern & Görev Durum Makinesi

Bir görevin kurallara aykırı olarak doğrudan TODO -> DONE olmasına izin vermeyen iş kuralı kısıtlaması:

TODO ➔ IN_PROGRESS ➔ IN_REVIEW ➔ DONE

Eğer bir geliştirici henüz incelemeye (IN_REVIEW) sunulmamış bir görevi doğrudan DONE yapmaya çalışırsa, TaskService.change_status anında ValueError fırlatır ve ACID kuralları gereği veritabanına hiçbir şey kaydedilmez.
